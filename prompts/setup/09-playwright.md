# Playwright MCP — проверка сайта в браузере

**Когда брать:** есть работающий сайт и разрешение владельца на тестирование.
**Результат:** проектное MCP-подключение и отчёт с проверенными сценариями.

## Установка

```prompt
Подключи официальный Microsoft Playwright MCP: пакет @playwright/mcp,
исходник https://github.com/microsoft/playwright-mcp.

1. Сверь текущую инструкцию Microsoft и установленную версию Claude Code.
2. До запуска пакета проверь исходный код, install scripts, зависимости и разрешения.
   Предложи точную версию, которую будем фиксировать; не используй непроверенный latest.
   Аудит снижает риск, но не доказывает безопасность.
3. После моего подтверждения добавь подключение только в текущий проект.
   Не перезаписывай существующий .mcp.json. Не вставляй литеральные токены: используй
   поддерживаемую подстановку окружения. Локальный .mcp.json не публикуем.
4. Используй отдельный тестовый профиль браузера без личных cookies и production-сессий.
   Ограничь разрешённые адреса и сеть; MCP и localhost сами по себе не sandbox.
5. Открой согласованную локальную тестовую страницу, сделай скриншот и покажи доступные
   инструменты из фактического подключения. Не объявляй установку успешной без проверки.
```

## Первый автотест

```prompt
Проверь согласованный тестовый сайт (например, http://localhost:3000).

1. Убедись, что это наше окружение, и опиши его зависимости. Localhost может обращаться
   к production-БД, платежам и внешним уведомлениям.
2. До подтверждения sandbox делай только read-only проверки: скриншоты, прокрутка,
   адаптивная вёрстка. Не отправляй формы, не нажимай «Купить», не создавай аккаунты.
3. Для теста отправки сначала нужны явное разрешение, тестовые аккаунты/БД, sandbox-
   платежи, заглушки писем/SMS/webhooks и план очистки тестовых записей. Если это не
   подтверждено, отметь сценарий как НЕ ПРОВЕРЕН, а не «работает».
4. Только в подтверждённом sandbox выполни согласованный сценарий с фиктивными данными
   (например, test@example.com), проверь результат и убери созданные записи.
5. Повтори разрешённые проверки на мобильном viewport. В отчёте раздели passed,
   failed и skipped; приложи скриншоты без персональных данных и токенов.
```

Не тестируй сторонние сайты без разрешения. Подключай лишь нужные MCP: объём их
описаний и расход контекста зависят от сервера, клиента и механизма загрузки инструментов.
