# Независимое ревью плана и судья

Когда: перед одобрением существенного плана или после изменения его объёма. Общий процесс — по ссылке из корневого `CLAUDE.md`/`AGENTS.md`.

```prompt
Проверь план [путь] целиком до реализации. Прочитай релевантный бизнес-контекст, каноническую архитектуру и фактическое состояние кода/тестов. Не проводи повторное интервью, если ответы уже есть.

Организуй независимое ревью: отдельные агенты/сессии или человек, не автор плана. Выбери направления и число рецензентов по риску, без фиксированной квоты. Проверь весь результат и все фазы: цель, реализуемость, UX, безопасность, зависимости, тесты, границы полномочий, лимиты, rollback и checkpoints.

Для каждого замечания нужны источник/пример, последствия и предлагаемое исправление. Судья проверяет обоснованность и принимает решение: принять / отклонить / отложить с причиной. Не принимай всё автоматически и не выдумывай замечания ради числа.

Внеси принятые правки в план, явно выдели открытые решения и представь итоговую версию на одобрение. Реализацию не начинай. Если независимое ревью недоступно, назови это блокером, не выдавай самопроверку за независимую.
```

После одобрения выполняется весь план; тот же цикл review → judge → fix → tests действует для реализации каждой фазы. Изменение production-полномочий согласуется отдельно.
