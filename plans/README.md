# plans/ — память исполнения

Сначала используй существующий активный план, даже если он находится в `architecture/10-implementation-plan.md`, а не в `plans/`. Не создавай дубликат. Если плана нет: один план — один согласованный результат, не обязательно одна функция. Он охватывает все фазы до готовности. Файл: `YYYY-MM-DD-название.md`, основа — [TEMPLATE.md](TEMPLATE.md).

Общий процесс читай по ссылке из корневого `CLAUDE.md` или `AGENTS.md`: `docs/workflow.md` в клоне, `.starter/workflow.md` в установленном проекте. Не дублируй здесь архитектуру — укажи её канонический путь.

До исполнения: независимое ревью плана → судья с решениями по замечаниям → исправления → одобрение владельца. Затем агент автономно проходит все одобренные фазы: реализация, тесты, независимое ревью, судья, исправления, повторные проверки, checkpoint. Никаких обязательных квот критиков и находок.

Фазы отмечаются `[x]` только при выполненных критериях. Checkpoint содержит команды и результаты проверок, review-решения, остаток, блокер и следующий шаг. При смене сессии сначала сверь его с реальными файлами. При лимите или выходе за полномочия остановись; одобрение плана не разрешает production-действия.

Закрывай план после итоговой интеграционной проверки. Незавершённое и непроверенное перечисляй явно. Существующие планы и шаблоны при установке не перезаписываются.
