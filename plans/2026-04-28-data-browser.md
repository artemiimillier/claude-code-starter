# План: браузер данных — просмотр, редактирование, поиск

**Дата:** 2026-04-28
**Статус:** реализован

## Цель

Страница `/dashboard/data` — просматривать проиндексированные сообщения Telegram, редактировать их руками, искать по всем данным.

## Стек

- Next.js App Router (существующий)
- MySQL FULLTEXT index — быстрый поиск по тексту без внешних зависимостей
- Семантический поиск (фаза 2+) — через векторные эмбеддинги в отдельной таблице

## Схема БД (новые таблицы)

```sql
messages (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  user_id       INT NOT NULL,
  chat_id       BIGINT NOT NULL,
  chat_name     VARCHAR(255),
  chat_type     ENUM('private', 'group', 'channel') DEFAULT 'private',
  message_id    BIGINT NOT NULL,
  sender_name   VARCHAR(255),
  text          TEXT NOT NULL,
  source        ENUM('import', 'live') DEFAULT 'import',
  original_date DATETIME,
  edited_at     DATETIME NULL,
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY (user_id, chat_id, message_id),
  FULLTEXT KEY ft_text (text, sender_name, chat_name),
  INDEX (user_id, original_date),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
)
```

## API роуты

```
GET  /api/data?q=&chat=&page=&limit=    ← список с поиском и фильтрами
GET  /api/data/[id]                     ← одно сообщение
PUT  /api/data/[id]                     ← редактирование текста
GET  /api/data/chats                    ← список чатов для фильтра
```

## Поиск

**Фаза 1 — FULLTEXT (MySQL):**
- `MATCH(text, sender_name, chat_name) AGAINST(? IN BOOLEAN MODE)`
- Подсветка совпадений на клиенте (substring highlight)
- Мгновенный результат, без новых зависимостей

**Фаза 2 — семантический (отложено):**
- Отдельная таблица `message_embeddings (message_id, embedding BLOB)`
- Генерация через выбранный AI-провайдер (из настроек connections)
- Поиск по косинусному расстоянию или через pgvector/hnswlib

## Критерии готовности

- [x] Можно найти сообщение по ключевому слову за < 500ms на 100k записей
- [x] Отредактированный текст сохраняется и подгружается при перезагрузке
- [x] Фильтр по чату работает независимо от поиска
- [x] Нет доступа к чужим данным (проверка user_id на API)

## Риски

- FULLTEXT в MySQL требует минимум 3 символа для поиска — для коротких запросов fallback на `LIKE %q%`
- Большой объём (1M+ сообщений) — добавить индекс по `(user_id, original_date DESC)` для сортировки без поиска
