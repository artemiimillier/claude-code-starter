# Второй мозг - правила работы с агентом

Персональный AI-ассистент, который читает переписки Telegram и отвечает на вопросы по ним через чат.

Подробности - в `.business/INDEX.md`.

## Структура репозитория

```
./
├── CLAUDE.md                ← этот файл, правила работы
├── TROUBLESHOOTING.md       ← решения типовых проблем Claude Code
├── .business/               ← скрытая папка, бизнес-контекст (не в git)
├── plans/                   ← технические планы (один план = одна функция)
├── retrospectives/          ← рефлексии после каждой сессии
└── prompts/                 ← библиотека готовых промптов
    └── INDEX.md             ← оглавление: если надо X - возьми Y
```

### Где что искать

| Что нужно | Куда смотреть |
|---|---|
| Зачем делаем проект, контекст | `.business/INDEX.md` |
| Продукт, интерфейсы, стадия | `.business/products/overview.md` |
| Цели, метрики | `.business/goals/` |
| Брендинг (цвета, шрифты) | `.business/assets/brand-guidelines.md` |
| Технические планы | `plans/` |
| Рефлексии прошлых сессий | `retrospectives/` |
| Операционное планирование | `.business/execution/` |
| Готовые промпты | `prompts/INDEX.md` |

## Стек

- **Backend:** Node.js
- **Источник данных:** Telegram Bot API + экспорт чатов
- **Поиск:** векторный (RAG)
- **Интерфейсы:** Telegram-бот, web-интерфейс (тёмная тема)
- **Шрифты:** Inter (UI) + Geist Mono (код)
- **Цвета:** `--accent-soft: #8ae3ee`, `--signal: #d7ff6f`, градиент `135deg`
- **Инфра:** выделенный сервер, приватный доступ

## Ключевые принципы работы

1. **Всегда читай `.business/INDEX.md`** перед задачей, связанной с логикой проекта.
2. **Один чат - одна задача.** Закончил - закрой чат, открой новый.
3. **Ищи в `prompts/INDEX.md` до того как писать промпт с нуля.**
4. **План для каждой новой функции** - в `plans/YYYY-MM-DD-название.md`:
   - Фазы со статусами `[ ]` / `[x]`
   - Итоговый блок: реализовано / что осталось
   - Актуализация плана после каждой сессии
5. **Ретроспектива в конце каждой сессии** - в `retrospectives/YYYY-MM-DD_HH-MM_название.md`.
6. **Коммить только свои изменения.** Никаких `git add .` - файлы поименно.
7. **Данные с коротким TTL** - в БД/конфиге, не в коде.

## Безопасность

- `.env` не читай целиком - только через `grep "^VAR_NAME=" .env`.
- Перед Bypass Permissions - git-коммит.
- Перед установкой любого скила / MCP - аудит через `prompts/setup/08-skills-install.md`.
- Telegram session token - никогда не передавай в промпты и не логируй.

## Триггеры операционного планирования

| Фраза | Действие |
|---|---|
| «давай спланируем неделю» | `.business/goals/monthly.md` → создай `.business/execution/YYYY-WNN.md` |
| «добавь задачу» | В файл текущей недели или в `.business/execution/backlog.md` |
| «что на этой неделе?» | Покажи файл текущей ISO-недели |
| «итоги недели» | Заполни секцию «Итог недели» |
